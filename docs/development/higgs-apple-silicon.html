③ 本次改了什么？

原有带种子采样路径

依赖 Triton + float64

种子和位置先参与哈希计算，再产生 Gumbel 随机扰动，最后选出音频代码。

MPS 无法直接执行这里的 Triton 内核和 float64 运算。

新增 MPS 兼容路径

这小段计算显式放到 CPU

保留所固定 SGLang 版本的哈希 / Gumbel 构造方式，算好后把选中的代码编号送回 MPS。

代价：增加 CPU 同步与数据传输；当前优先验证正确性。

MPS

对数概率 + 种子 + 位置

输入概率已完成 top-k / top-p 过滤。
→
CPU · 新增兼容层

哈希 → 随机扰动 → 选取

整数运算和 float64 都在 CPU 完成。
→
回到 MPS

选中的音频代码编号

继续原有延迟 / 结束状态机。

种子的作用：给定相同输入、种子和生成位置，结果应可重复；其他请求插入批次，不应改变这一行的结果。不同后端的模型数值可能不同，所以这不代表最终生成的声音一定逐字节一致。

Mac 实测修复：先用 .detach().cpu() 把对数概率传到 CPU，再转换成 float64。原先合并设备与类型转换的写法导致 5 项 MPS 测试失败；拆开后全部通过。

⑤ 如何复现 Apple Silicon 测试？

使用 fork 上的此分支，并包含本地 CPU 转换修复。以下命令均在仓库根目录执行。完整项目要求 Python 3.10–3.12；Apple 安装脚本使用 Python 3.12。

A · 无需模型下载

先验证数值与 Metal 往返

只需要原生 arm64 Python、Torch 与 pytest。

python3.12 -m venv /tmp/higgs-apple-sampling-venv
source /tmp/higgs-apple-sampling-venv/bin/activate
python -m pip install torch==2.11.0 pytest

env -u PYTORCH_ENABLE_MPS_FALLBACK HIGGS_REQUIRE_MPS=1 \
  python -m pytest -v \
  tests/unit_test/higgs_tts/test_apple_sampling.py

预期：15 项通过，0 跳过。

B · 完整 Apple 环境

再验证真实 Higgs 采样器

切换到匹配此仓库依赖的 SGLang-Omni Apple 环境；A 的最小环境不足以运行此组。

# 若已激活 A 的环境，先执行 deactivate
./install.sh
source .venv-apple/bin/activate

env -u SGLANG_USE_MLX \
  -u PYTORCH_ENABLE_MPS_FALLBACK \
  HIGGS_REQUIRE_MPS=1 \
  python -m pytest -v \
  tests/unit_test/higgs_tts/test_apple_sampler_integration.py

预期：3 项通过，0 跳过。

HIGGS_REQUIRE_MPS=1 会在没有 Metal 时直接报错，避免“跳过”被误读为“通过”。关闭隐式 CPU 回退是为了发现不支持的运算；本次实现中明确设计的 CPU 采样边界仍会执行。
